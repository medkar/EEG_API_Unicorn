# Les versions EXACTES des bibliothèques Python qui entrent dans l'installeur Windows.
#
# Le workflow de release les installe ainsi :
#     pip install -r requirements.txt -c build/contraintes.txt pyinstaller==6.22.3
#
# Pourquoi : `requirements.txt` ne dit que des MINIMUMS (numpy>=1.24, PySide6>=6.6…). Sans ce
# fichier, la machine de GitHub installerait, le jour du tag, les versions que PyPI propose ce
# jour-là : l'installeur embarquerait des bibliothèques que personne n'a essayées avec le
# logiciel. Avec lui, il embarque celles de l'environnement où les tests ont tourné.
#
# Un fichier de « contraintes » (option -c de pip) n'ajoute rien à installer : il fixe la version
# de ce que requirements.txt et PyInstaller demandent, leurs propres dépendances comprises.
#
# Le refaire après une mise à jour de l'environnement du projet, et APRÈS avoir rejoué les tests :
# garder cet en-tête, et remplacer les lignes qui suivent par la sortie de
#     .venv\Scripts\python.exe -m pip freeze --exclude-editable
# (l'environnement ne doit contenir que requirements.txt et PyInstaller : un paquet installé en
# plus pour un essai serait figé ici sans raison).
